# x-release — SRE

## 核心原则

**不能回滚的发布不算发布，等于拿生产环境当试验场。**

上线前必须能回答三个问题：怎么知道它好了、怎么知道它坏了、坏了怎么退回去。

## 何时不用

- 改动不改变生产行为（纯注释、纯测试、纯文档）→ 不需要发布计划，贴证据即可。
- 没有生产环境、没有回滚需求（本地工具、一次性脚本）→ 写明"无生产影响"就够。
- 你在讨论"要不要发"而不是"怎么发" → 那是决策，不是发布计划。

## 输入 / 输出

- 输入：`02-design.md`、`03-impl.md`、`04-test.md`、`05-security.md`
- 输出：`06-release.md`（门禁 G6）

## 流程

1. **定影响面**：这次改动影响哪些请求路径、多少流量比例、哪些用户或租户、哪个依赖。说不出比例的写"未知"并说明怎么测出来。
2. **算放大效应**：重试次数上升、并发上升、轮询频率变化、批量变大，都会改变对外部依赖的请求量。**算一遍峰值，和对方配额比。**
3. **定 SLO 影响**：这次改动会让哪个指标变差？错误预算还剩多少？说不清 = 还没搞懂这次改动。
4. **定信号**：两类都要有——
   - **证明正常**：哪个指标、日志或追踪能证明新行为按预期发生了（不是"服务还活着"）
   - **证明异常**：哪个指标会在 5 分钟内变红，阈值是多少
5. **定发布策略**：全量还是分阶段（1% → 10% → 100%）；每阶段观察窗口多长；什么条件自动停。
6. **定回滚**：具体到命令、开关或版本号；回滚后怎么验证已经退回去了；回滚会不会丢数据、会不会和已发生的副作用冲突（重试、扣款、发消息）。
7. **写 runbook**：值班的人半夜被叫起来，看到这一段能不能自己处理。写不了 = 没准备好。
8. **定观察责任**：谁盯、盯多久、超时无人响应怎么办。

## 输出格式 `06-release.md`

```markdown
## 影响面
| 路径 | 流量比例 | 受影响用户 | 外部依赖 |

## 放大效应
| 依赖 | 改前峰值 | 改后峰值 | 配额 | 余量 |

## SLO 影响
<哪个指标、变差多少、错误预算余量>

## 信号
| 类型 | 指标 / 日志 | 阈值 | 观察窗口 |
（证明正常 / 证明异常 各至少一条）

## 发布策略
| 阶段 | 比例 | 观察窗口 | 自动停条件 |

## 回滚
- 步骤：<具体操作>
- 回滚后验证：<命令 → 预期输出>　例：`<健康检查命令>` → `200 OK`
- 数据影响：<会不会丢、会不会重复>

## Runbook
<值班可执行的处理步骤>

## 观察责任
- 谁：<...>　盯多久：<...>
```

证据统一按 `x-quality` 的证据格式写。**流量比例、峰值、配额这些数字，拿不到就写「未验证：缺什么」，不许估一个看起来合理的数。**

按「结论优先」写：影响面、放大效应、回滚结论先给，排查过程不写。回滚步骤和 Runbook 是交付物，逐步写全。

## 门禁 G6

- 影响面能说出比例（或写明如何测得）
- 有"证明正常"和"证明异常"两类信号，各至少一条，带阈值
- 有可执行的回滚步骤 + 回滚后验证方法
- 回滚的数据副作用已说明（重复扣款、丢消息、脏数据）
- 变更窗口符合团队约定（临近周末或节假日的资金类变更默认不批）
- 有 runbook，且是给"不了解这次改动的人"看的

## 禁止

- 只写"部署步骤"，不写回滚
- 用"观察一下"代替阈值
- 用"服务存活"当成功信号（活着不等于对了）
- 跳过放大效应计算（重试、轮询、批处理类改动必算）
- 把"有问题再说"当发布策略

## 借口与回应

| 借口 | 现实 |
|---|---|
| "改动很小，不用回滚方案" | 小改动也会挂。回滚方案五分钟能写完 |
| "监控都有，不用单独定信号" | 有监控 ≠ 有这次改动的信号。通用 CPU 曲线看不出重试逻辑错了 |
| "先全量发，有问题再回滚" | 那就是拿全量用户当灰度 |
| "回滚就是把版本退回去" | 那已经发生的副作用怎么办？写清楚 |
| "周五发，周末有问题周一处理" | 周末无人值守 = 故障时长乘以 48 |
| "值班的看监控就知道了" | 看监控不知道该怎么办。写 runbook |
| "这是纯内部改动，不影响用户" | 内部改动也会把上游拖垮。写出影响链 |

## 红旗

- `06-release.md` 里没有"回滚"一节
- 信号只有 CPU、内存、存活
- 重试或轮询类改动没有放大效应计算
- runbook 里出现"联系作者"（作者可能不在）
- 发布计划里没有观察窗口
- 回滚步骤里出现"重新部署旧版本"却没有旧版本号
