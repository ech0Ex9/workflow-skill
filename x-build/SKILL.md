# x-build — 开发者

## 核心原则

**一次只让一个测试从红变绿。**

不预测下一个测试，不实现设计里没有的东西。

## 输入 / 输出

- 输入：`00-brief.md`、`02-design.md`（L2 及以上）、`x-quality`
- 输出：代码 + `03-impl.md`（门禁 G3）

## 流程（垂直切片）

对每条验收标准：

1. 在**设计指定的接缝**上写一个会失败的测试，跑一遍，确认它失败（红）。
2. 写刚好能让它通过的最小实现（绿）。
3. 跑项目自带的检查（类型检查、lint、单测），全绿。
4. 下一个切片。

**不要横着切**（先写完所有测试再写实现）：那样测的是想象的形状，不是真实行为。

全部切片完成后：

5. 按 `x-quality` 的 14 条逐条自检，把"结论 + 证据"写进 `03-impl.md`。
6. 与设计有偏差的，逐条写"偏差 + 原因 + 影响"，不要偷偷改设计。

## 硬约束

来自质量宪法，逐条可查：

- `QS-01` 不留死代码：没有调用方的导出、占位实现、注释掉的代码
- `QS-02` 不造抽象：新 interface / 类 / 工厂必须有 ≥2 个当前调用方
- `QS-03` 不硬编码：业务数字、字符串、超时、阈值全部命名
- `QS-04` 默认值一处定义
- `QS-05` 不在模块顶层读环境、开定时器、建全局单例
- `QS-12` 不做任务外的重构和格式化
- `QS-13` 外部依赖从边界注入（时间、随机、网络、存储）

## 输出格式 `03-impl.md`

```markdown
## 改动清单
| 文件 | 改动 | 对应验收标准 |

## 切片记录
| # | 测试（红→绿） | 证据（`命令 → 输出` / `文件:行 → 原文`） |

## 质量自检
QS-01 PASS  <命令 → 输出 或 文件:行 → 原文>
QS-02 PASS  <...>
...
QS-14 PASS  <...>

## 与设计的偏差
- <偏差> —— 原因：<...> —— 影响：<...>

## 未完成 / 已知缺口
- <...>
```

## 门禁 G3

- 每条验收标准都有对应改动
- 14 条 QS 逐条有结论 + 证据，证据按 `x-quality` 的证据格式写（不是"已检查"三个字）
- 项目自带检查零新增告警，贴输出
- 偏差已记录，没有静默偏离设计
- 生产代码里没有"以后再补"的 TODO

## 禁止

- 给自己签 G3（自审不算）
- 顺手重构、顺手格式化、顺手改名（`QS-12`）
- 为了让测试过而改测试（改测试 = 改需求，要走回 G0）
- 删除失败的测试
- 用类型逃逸（`any`、忽略注释、强转）压掉错误
- 留 `// TODO` 占位实现上线
- 加"以后可能要用"的参数、配置、分支

## 借口与回应

| 借口 | 现实 |
|---|---|
| "先写实现，测试回头补" | 回头补的测试是给实现写的说明书，抓不到 bug |
| "这个抽象以后肯定有用" | 数当前调用方。`QS-02` |
| "加个 try/catch 别让它崩" | 空 catch 是把崩溃换成静默错误。`QS-07` |
| "这个值以后可能要改，先写死" | "可能"不是需求。要改就现在命名 |
| "测试挂了但不是我改的" | 先证明。拿不出证据就是你的改动 |
| "这个重构很小，顺手" | 顺手改动扩大评审面。`QS-12` |
| "类型报错，加个 any 先过" | 类型逃逸是把错误推迟到运行时 |
| "先合进去，我再优化" | 合进去的临时方案会活很久。优化现在做，或写进缺口 |

## 红旗

- 测试文件没有"红"的记录，只有一次绿
- `03-impl.md` 里 QS 结论全是 PASS 却没有证据
- diff 里出现与 brief 无关的文件
- 新增了导出但没人 import
- 代码里有 `TODO`、`FIXME`、注释块
- 新增了配置项但没有任何代码读它
