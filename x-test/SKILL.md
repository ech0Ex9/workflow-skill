# x-test — 测试

## 核心原则

**没有输出就没有通过。**

"应该能过""本地没问题"不是测试结论。

## 输入 / 输出

- 输入：`00-brief.md`、`02-design.md`、`03-impl.md`
- 输出：`04-test.md`（门禁 G4）

## 流程

1. **建立映射**：每条验收标准 → 至少一个用例。**映射表先写出来，再写测试。**
2. **补边界**：空值、零、负数、上限、超限、并发、超时、部分失败、重复提交、乱序。**每个数值阈值测两侧**（`≤` 与 `>`），断言输入变大时结果不反向（更贵 / 更慢 / 更少）。
3. **补错误路径**：失败时返回什么？错误可区分吗？重试安全吗（幂等）？失败会静默吗？
4. **只在设计指定的接缝测**：接缝之外的内部实现不测。测了实现 = 重构就红 = 假测试。
5. **期望值独立**：手算样例、规格原文、已知正确字面量。不许用被测代码的算法算期望值。
6. **跑，贴输出**：完整命令 + 完整输出 + 退出码。失败就是失败。
7. **写未覆盖项**：哪些没测、为什么、风险多大。诚实比覆盖率数字有用。

## 输出格式 `04-test.md`

```markdown
## 验收标准映射
| 验收标准 | 用例 | 结果 |

## 边界与错误路径
| 场景 | 用例 | 结果 |

## 接缝
| 接缝 | 覆盖 | 未覆盖原因 |

## 证据
<命令> → <关键输出 + 退出码>

例：`<项目测试命令>` → `7 passed, 0 failed`（exit 0）
例：`<项目类型检查命令>` → `无输出`（exit 0）

## 未覆盖与风险
```

证据按 `x-quality` 的证据格式写：命令 → 输出，或 文件:行 → 原文。不许只写「测试通过」。

## 门禁 G4

- 每条验收标准都有用例，且有结果
- 边界与错误路径有覆盖，或写明为什么不需要
- 每个数值阈值有两侧用例，且断言单调
- 测试在公共接缝，不 mock 内部协作者
- 期望值不来自被测实现
- 有红→绿证据（不是只有最终绿）
- 未覆盖项写明风险
- 没有删改失败测试来"通过"

## 禁止

- 删掉失败的测试
- 改断言去迁就实现（那是改需求，走回 G0）
- 用覆盖率当结论（覆盖率 90% 但没测错误路径 = 没测）
- 把"手动点了一下没问题"当 G4 证据（除非写明点了什么、看到什么）
- 自己写实现、自己测，且不换上下文（同一个人同一次会话 = 自审）

## 借口与回应

| 借口 | 现实 |
|---|---|
| "实现很简单，不用测" | 简单代码的错误最贵，因为没人怀疑它 |
| "覆盖率够了" | 覆盖率测的是行被执行，不是行为被验证 |
| "这个边界不可能发生" | 写下"不可能"的原因。写不出就测 |
| "测试太慢，先跳过" | 慢测试会被永久跳过。要么修快，要么标风险 |
| "本地跑过了" | 贴输出。没有输出 = 没跑 |
| "失败的是环境问题" | 证明它。拿不出证据就是代码问题 |
| "这是历史遗留问题，不是我改的" | 先证明。证明不了就写进未覆盖与风险 |

## 红旗

- 只有 happy path
- 所有断言都是"不抛异常"
- 测试里出现内部类的 mock
- 期望值是被测函数的复制品
- 报告里没有命令输出
- 用例数量与验收标准数量对不上
