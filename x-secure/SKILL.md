# x-secure — 安全

## 核心原则

**没有攻击路径，就没有严重级别。**

安全问题不是"感觉不安全"，是"谁能从哪一步做到什么"。

## 输入 / 输出

- 输入：`01-explore.md`（风险面）、`02-design.md`（接缝）、`03-impl.md`（改动）
- 输出：`05-security.md`（门禁 G5）

## 流程

1. **画信任边界**：哪里是外部（用户、第三方、文件、环境），哪里是内部。边界每跨一次，都要有校验。
2. **枚举入口**：每个入口 → 谁能访问 → 需要什么凭据 → 校验在哪一行。
3. **逐问过**：每个入口回答六个问题。能写出路径的进 findings，写不出的进 note 并写原因。
   - 谁能冒充别人
   - 谁能改数据不被发现
   - 谁能事后否认做过
   - 谁能读到不该读的
   - 谁能让服务停
   - 谁能提权
4. **确认面**：哪些面存在——鉴权与越权、输入信任、密钥与凭据、出网与依赖、文件与进程、资金与幂等。存在的面逐个用上一步的六问扫一遍。
5. **每条发现写攻击路径**：`入口 → 步骤 → 结果`。写不出路径的，降级为 `note`，不给级别。
6. **给可复现证明**：最小 PoC、静态推导、或本地夹具验证。**禁止对真实服务做破坏性验证。**
7. **给修法**：修在哪一层、为什么修在那层（在入口校验还是在业务层校验，结论要能解释）。

## 输出格式 `05-security.md`

```markdown
## 结论
<能不能上：能 / 不能 / 有条件上；一句话>

## 信任边界
| 边界 | 跨边界的数据 | 校验位置 |

## 入口清单
| 入口 | 访问者 | 鉴权 | 校验位置 |

## 六问覆盖
| 问句 | 命中的入口 | 不适用原因 |
（六行齐全，不适用的写原因，不许留空）

## 发现
### FINDING-1 <标题>
- 攻击路径：<入口> → <步骤> → <结果>
- 证据：<`文件:行 → 原文` 或 `<请求 → 响应>` 或 `未验证：<缺什么>`>
- 根因：<CWE 类别>
- 严重级别：<基于可达性与影响>
- 修法：<改哪一层>

## note（无攻击路径，不计入门禁）
```

证据统一按 `x-quality` 的证据格式写。攻击路径本身就是证据链，路径里每一步都要能落到 `文件:行 → 原文`，落不到的那一步就是猜的。

发现正文按「结论优先」写：`FINDING-1` 先给结论，排查顺序不写。攻击路径是交付物，保留完整链条。

这份产物要让人决定「能不能上」，按 `x-report` 的对应必答序列组织：结论 → 攻击路径 → 影响 → 修法，缺一问不算完成。

上面的表格按 `x-report`「呈现：矩阵」排：拿不到的格子写 `未验证：<缺什么>`，不许用等级词填满。

## 门禁 G5

- 每条发现都有攻击路径，否则降级为 note
- 六个问句各回答一次；答「不适用」要写原因
- 触及鉴权、资金、用户数据的入口全部列出，且能指出校验所在行
- 有可达攻击路径的发现 = **阻断**，不是"建议修复"
- 密钥类问题：仓库内零硬编码凭据
- 没有对真实环境做破坏性验证

## 禁止

- 报"可能存在 XX 风险"却不给路径
- 用通用清单刷存在感（每条都要落到本项目的 `file:line`）
- 对线上服务跑破坏性 PoC
- 把"内部服务所以不用鉴权"当结论（内部也是边界）
- 只报"输入未校验"却不说明能造成什么后果

## 借口与回应

| 借口 | 现实 |
|---|---|
| "内网接口，没人能访问" | 内网也是边界。写清楚谁能到，再决定 |
| "参数是前端传的，不会有人改" | 前端不是信任边界。改包成本为零 |
| "这里理论上可能有问题" | 给路径，或者写 note。理论问题既不阻断也不放行 |
| "安全扫描没报" | 扫描器不懂业务逻辑。越权它测不出来 |
| "先上线，安全下个迭代补" | 有可达路径的问题上线 = 已知漏洞上线 |
| "这是内部工具，不用这么严" | 内部工具也连着生产数据和员工账号 |

## 红旗

- 发现全是"建议加强""注意防范"
- 没有入口清单
- 鉴权结论只有"有中间件"
- 错误响应把堆栈或内部路径返回给调用方
- 日志里出现 token、密钥、完整用户数据
- 严重级别来自直觉而不是可达性
